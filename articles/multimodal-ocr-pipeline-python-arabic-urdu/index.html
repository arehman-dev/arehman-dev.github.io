Building a Multimodal OCR Pipeline in Python for Arabic & Urdu Nastaliq Texts

September 28, 2026 11 min read

Digitizing classical bilingual textbooks—specifically Arabic grammar works written in Urdu such as Aasan Arabi Grammar (346 pages) and Lisan ul Quran (433 pages)—presents a notorious engineering bottleneck. Standard tools like pdftotext and traditional optical character recognition engines like Tesseract routinely fail on these documents.

1. Why Traditional Extraction Fails

  • Corrupted Font CMaps: Legacy Urdu typesetting software frequently embeds non-standard character maps for Nastaliq fonts (such as Jameel Noori Nastaliq or Alvi). Direct PDF text extraction scrambles code points (turning د into ز) and strips essential Arabic diacritics (Zabar, Zer, Pesh, Sukun, Shaddah).
  • Complex Ligatures & Watermarks: In scanned PDFs with heavy central watermarks and multi-column conjugation tables (Gardan), traditional OCR loses reading order and merges Arabic morphology tables into unreadable lines.

2. Architecture of the Vision OCR Pipeline

To solve this without installing multi-gigabyte local PyTorch dependencies, I architected a lightweight, zero-SDK Python CLI pipeline using poppler-utils (pdftoppm), standard requests, and concurrent worker pools backed by multimodal Vision models:

#!/usr/bin/env python3
import base64
import subprocess
from pathlib import Path
from concurrent.futures import ThreadPoolExecutor, as_completed

def render_pdf_page(pdf_path: Path, page_num: int, out_dir: Path) -> Path:
    prefix = out_dir / f"page_{page_num:03d}"
    cmd = [
        "pdftoppm", "-png", "-r", "300",
        "-f", str(page_num), "-l", str(page_num),
        str(pdf_path), str(prefix)
    ]
    subprocess.run(cmd, check=True, capture_output=True)
    return next(out_dir.glob(f"page_{page_num:03d}*.png"))

3. Enforcing Diacritic Fidelity & Markdown Table Layout

The system prompt instructs the vision endpoint to preserve 100% of Arabic vocalization marks (Tashkeel), transcribe Urdu Nastaliq verbatim without modernizing spelling, ignore decorative page borders/watermarks, and convert grammatical paradigm grids directly into GitHub-Flavored Markdown tables.

4. Idempotent Resume & Fault Tolerance

When processing 700+ pages over network APIs, rate limits (HTTP 429) and transient timeouts are inevitable. The pipeline writes each completed page immediately to output/<book>/pages/page_NNN.txt:

def process_book(pages: list[int], max_workers: int = 3):
    pending = [p for p in pages if not (PAGES_DIR / f"{p:03d}.txt").exists()]
    with ThreadPoolExecutor(max_workers=max_workers) as pool:
        futures = {pool.submit(transcribe_page_with_retry, p): p for p in pending}
        for future in as_completed(futures):
            page_no = futures[future]
            text = future.result()
            (PAGES_DIR / f"{page_no:03d}.txt").write_text(text, encoding="utf-8")

If interrupted at page 240, re-running the command automatically skips pages 001–240, finishes the remaining pages, and concatenates all individual page transcripts into a single clean UTF-8 master corpus.
