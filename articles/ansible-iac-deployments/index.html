Infrastructure as Code (IaC): Declarative vs. Imperative Provisioning with Ansible & Terraform

February 22, 2026 9 min read Verified Technical Content

Configuring servers manually via interactive SSH sessions leads to "configuration drift"—over time, no two machines have the exact same packages, sysctl parameters, or service files. Infrastructure as Code (IaC) solves this by treating server topology and configuration as version-controlled source files.

1. Declarative vs. Imperative Models

When evaluating modern DevOps toolchains—such as Terraform, Kubernetes, and Ansible—the most fundamental architectural distinction is how they model state:

  • Declarative (Terraform, Kubernetes Manifests): You declare the desired end state (e.g., "3 container replicas running image v1.2 with port 8080 exposed"). The engine diffs the current state against your manifest and computes the necessary transitions automatically.
  • Procedural / Hybrid Idempotent (Ansible): You define an ordered sequence of tasks (playbooks) executed top-to-bottom. While each individual Ansible module (like apt or systemd) is idempotent, execution order is explicitly controlled by the engineer.

2. Agentless Configuration with Ansible

For Linux workstation and single-node server standardization, Ansible's agentless design is a major advantage—it requires zero background daemons on the target host, relying strictly on SSH and Python:

- name: Standardize Ubuntu Workstation Environment
  hosts: workstations
  become: true
  tasks:
    - name: Ensure core CLI monitoring and terminal packages are installed
      ansible.builtin.apt:
        name:
          - btop
          - tmux
          - git
          - ntfs-3g
        state: present
        update_cache: true

    - name: Ensure Docker Engine service is enabled and active
      ansible.builtin.systemd:
        name: docker
        enabled: true
        state: started

3. Choosing the Right Tool for the Layer

In practice, these tools complement rather than replace each other: use Terraform to provision the underlying compute and network primitives, Ansible to harden the Linux OS and configure systemd daemons, and Docker / Kubernetes to orchestrate the containerized workloads on top.
